# الدَّين التقني

> `standards/platform.md §١٢`: الدَّين يُقبل مكتوباً **بسبب وشرط معالجة وشرط انقلاب** — أو لا يُقبل.
> **هذا الملف يُراجَع بداية كل جلسة.**

---

## د-١ · الحزمة السابعة من مخطط البذرة مؤجَّلة

| الحقل | القيمة |
|---|---|
| **ما هو** | `seed-blueprint §٢/الحزمة ٧`: توليد `STATUS.md` · توثيق اختبار الاستعادة · إجراء تدوير المفاتيح · مراجعة محايدة · دليل الصفر · وسم `seed-v1`. مؤجَّلة إلى ما بعد تشغيل سنن. |
| **السبب** | حزم ١–٦ هي أساس سنن نفسها بلا استثناء. الحزمة ٧ تعميمٌ عائده على المنصات القادمة (مِحك، بادل) لا على هذه، وتقديمها يؤخّر المنصة بعمل مؤجَّل الفائدة. |
| **شرط المعالجة** | تُنفَّذ كاملة بعد قبول الحزمة السادسة وتشغيل سنن. |
| **شرط الانقلاب** | **تُنفَّذ إلزاماً قبل بدء أي منصة ثانية.** بدء منصة ثانية بلا بذرة موسومة يعني نسخاً يدوياً ينحرف — وهو الفشل الذي وُجدت البذرة لمنعه. |
| **المرجع** | `docs/adr/0009` |
| **الحالة** | مفتوح · مسجَّل ٣١ أغسطس ٢٠٢٦ |

**تنبيه:** بندان من الحزمة ٧ ليسا تعميماً بل أماناً تشغيلياً — **اختبار الاستعادة** و**تدوير المفاتيح**. و`platform.md §٥` يوجب خطة استعادة **مُختبَرة مرة قبل أول بيانات حقيقية** («النسخة غير المختبَرة ليست نسخة»). هذان لا يُؤجَّلان مع بقية الحزمة، بل يُنفَّذان في موضعهما من `§١٥`.

## د-٢ · التمديد فوق المخطَّط وآلية السقف مؤجَّلان

| الحقل | القيمة |
|---|---|
| **ما هو** | لا يستطيع المشارك تسجيل إنجاز فوق المخطَّط. ومعه يسقط السقفان (يومي ٣٠٪ · إجمالي ١٥٪) والطبقات الثلاث للرقم. |
| **السبب** | بلا تمديد، التجاوز مستحيل بنيوياً — فالسقف لا ينطبق قط، وبناؤه نائماً هدر يمنعه `platform.md §١٢`. |
| **شرط المعالجة** | يُقاس بعد أول دورة: عدد المشاركين الذين طلبوا تجاوز خطتهم فعلاً. |
| **شرط الانقلاب** | إن ثبت الطلب، يُفعَّل التمديد وتُضاف **دالة سقف عند حساب الترتيب وحده** — لا إعادة بناء. |
| **المرجع** | `docs/adr/0014` · يُقيِّد `adr/0007` |
| **الحالة** | مفتوح · مسجَّل ٣١ أغسطس ٢٠٢٦ |

## د-٣ · طبقة المسابقة مؤجَّلة لمرحلة ثانية

| الحقل | القيمة |
|---|---|
| **ما هو** | بنك الأسئلة · التصفيات · الجلسات · التحكيم · النتائج · الإحصائيات · الجزاءات. ومعها الجلسة المتزامنة في `adr/0002` و`0013`. |
| **السبب** | إخراج دورة متابعة حفظ عاملة أولاً — وهي أطول أجزاء تجربة المشارك زمناً وأبكرها موعداً. |
| **شرط المعالجة** | تُبنى المرحلة الثانية بعد قبول الأولى كاملة. |
| **شرط الانقلاب** | **عند تثبيت موعد دورة المسابقة.** إن لم يتّسع الموعد للمرحلتين، فالخيار بين تقليص الأولى أو تأجيل الدورة. |
| **الأخطر فيه** | المرحلة الأولى **لا تُكمل دورة مسابقة** — لا نتائج ولا جوائز. المرحلة الثانية على المسار الحرج لا خارجه. |
| **المرجع** | `docs/adr/0022` |
| **الحالة** | مفتوح · مسجَّل ٢ سبتمبر ٢٠٢٦ |

## د-٤ · تأكيد البريد مُطفأ حتى يُضبط مزوّد بريد

| الحقل | القيمة |
|---|---|
| **ما هو** | الزائر يُنشئ حسابه (`/sign-up`) ويدخل فوراً دون تأكيد أنه يملك البريد. |
| **السبب** | بريد Supabase المجاني يُرسل رسائل قليلة في الساعة، فتأكيد البريد اليوم يُعلّق أغلب المسجِّلين يوم الإعلان. |
| **شرط المعالجة** | يُضبط SMTP في Supabase، ثم يُفعَّل **Confirm email**، ويُعدَّل قالب «Confirm signup» إلى `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email&next=/dashboard`. الشاشة تتعامل مع الحالتين أصلاً. |
| **شرط الانقلاب** | **قبل الإطلاق للجمهور.** وقبل ذلك إن ظهرت حسابات ببُرد لا يملكها أصحابها. |
| **الأخطر فيه** | من أخطأ في كتابة بريده لا تصله رسالة استعادة كلمة المرور. |
| **الحالة** | مفتوح · مسجَّل ١٥ سبتمبر ٢٠٢٦ |

## د-٥ · ما لم تُغطّه مراجعة المرحلة الأولى

| البند | لماذا ليس الآن | شرط المعالجة |
|---|---|---|
| **شاشة الإعدادات** | حدود المحاولات وغيرها تُعدَّل في القاعدة، ولا تتغيّر في التشغيل العادي | أول إعداد يحتاج الراعي تغييره بنفسه |
| **الإشعارات والتذكير اليومي** | القناة لم تُحسم (ف-٥) | حسم ف-٥ |
| **تصدير المشاركين** | لا طلب تشغيلي بعد | أول تقرير تطلبه الجمعية |
| **رفع ملف الخطة** | اللصق يؤدّي الغرض نفسه | خطة تُعدّ خارج المنصة في ملف |
| **البحث والفرز والصفحات في الجداول** | الجدول الجامع يكتبها في الرابط ولا تقرؤها الصفحات | قائمة تتجاوز صفحة واحدة في التشغيل (المشاركون أولها) |
| **مستخدمو شاشة الأدوار** | قائمة الإسناد تجلب كل الملفات، والمشاركون صاروا ملفات | تجاوز المستخدمين ألفاً |

**الحالة:** مفتوح · مسجَّل ١٥ سبتمبر ٢٠٢٦
